================================================================================
第一章 简介
================================================================================
ASIO Bridge 是一个 Windows 音频直通桥:
  把任意目标应用(Apple Music、浏览器、播放器、游戏)的渲染音频,
  用 Windows 11 原生「进程回环(Process Loopback)」按 PID 旁路采集,
  绕过 Windows 引擎的混音/重采样/APO,
  经过自研 DSP 链(速率锁+分数重采样+TPDF抖动+300B电子管染色+
  厚度与宽度+火箭推进器),
  最后经 输出后端(ASIO 或 WASAPI 独占) 送到你的声卡/DAC。

特点:
  - 免虚拟声卡、免第三方驱动、不占麦克风
  - 目标进程自动发现/切换(锁定「最响的渲染进程」)
  - 输出设备自动扫描, 按设备能力自动选择 ASIO 或 WASAPI 独占
  - 内嵌复古金属风 Web 控制台(实时水位/频谱/全部音色调参)
  - 6 套数值自检(先测后上线)
  - 崩溃自愈(驱动级崩溃自动拉起新实例)

架构(数据流):
  目标应用 → Windows 引擎(audiodg)
            → 进程回环按 PID 旁路取流(float32)
            → 环形缓冲(SPSC 无锁)
            → 速率锁 + 分数重采样(sinc/线性)
            → TPDF 抖动 + 300B 染色 + 厚度与宽度 + 火箭推进器
            → 输出后端: ASIO 驱动 或 WASAPI 独占
            → 声卡/DAC

================================================================================
第二章 环境要求
================================================================================
  - Windows 11 22H2 或更高(进程回环 API 的最低要求)
  - x64 架构
  - 音频硬件: 任意声卡/DAC
      * 有 ASIO 驱动的专业声卡(如 RME MADIface): 走 ASIO, bit-perfect
      * 无 ASIO 驱动的消费级设备(USB DAC/耳机/板载声卡): 走 WASAPI 独占
  - 构建工具(仅构建需要):
      Visual Studio 2022 Community(C++ 桌面开发负载 + CMake)
      或 直接使用已编译的 build\Release\asio_bridge.exe

================================================================================
第三章 构建
================================================================================
方法一: CMake + VS2022(推荐)
  cmake -B build -S .
  cmake --build build --config Release
  产物: build\Release\asio_bridge.exe

方法二: 命令行 cl.exe(不依赖 CMake GUI)
  cmd /c tools\rebuild.cmd
  产物: build\Release\asio_bridge_new.exe
  (停掉正在运行的桥, 再改名覆盖为 asio_bridge.exe)

说明: 仓库已内嵌 Steinberg ASIO SDK 2.3(third_party\ASIOSDK2.3),
      无需单独下载。

第四章 快速开始(30 秒上手)
================================================================================
1) 启动桥(推荐加 --log 便于查看):
     build\Release\asio_bridge.exe --log C:\Users\你的名字\asio_bridge.log

2) 播放任意应用音频(浏览器/播放器/游戏)。
   桥 10~20 秒内自动锁定「最响的渲染进程」。

3) 打开控制台:
     浏览器访问 http://127.0.0.1:3999
   观察: 水位稳定、欠载=0、峰值随音乐起伏 → 正常。

4) (可选)切换输出设备:
   控制台 CONTROL DECK → 输出设备 → 下拉选择 → 桥自动重建。

5) 停止: Ctrl+C(前台) 或 控制台 ASIO Bridge 按钮(灰=停, 红=开)。

常见命令行用法:
  asio_bridge                      # 桥接模式(默认输出: 自动选择)
  asio_bridge --driver "Realtek ASIO"   # 指定 ASIO 驱动(旧方式)
  asio_bridge --tone --rate 44100  # 1kHz 测试音(验证声卡链路)
  asio_bridge --list               # 列出 ASIO 驱动

第五章 命令行参数详解
================================================================================
asio_bridge                             桥接模式(默认)
asio_bridge --list                      列出 ASIO 驱动
asio_bridge --tone                      1kHz 正弦测试(验证声卡/ASIO 链路)
  --rate <Hz>                           tone 模式采样率(默认 44100)
asio_bridge --driver <名字>             指定 ASIO 驱动
                                        (默认 "ASIO MADIface USB";
                                         现控制台设备选择可替代本参数)
asio_bridge --buffer <帧数>             ASIO 缓冲帧数(默认驱动值;
                                        低延迟可试 128/64)
asio_bridge --log <文件>                输出追加写入日志文件(后台/自启用)
asio_bridge --no-dither                 关闭 TPDF 抖动(默认开启)
asio_bridge --passthrough               直通模式: 停用重采样(ratio 恒 1.0,
                                        逐位直通, 漂移交给环形缓冲)
asio_bridge --no-mute                   诊断: 跳过端点静音(会出现双重声)
asio_bridge --resampler-test            重采样器正弦离线自检
asio_bridge --pll-test                  速率锁+水位闭环联合仿真自检
asio_bridge --tube-test                 300B 染色数值自检
asio_bridge --conv-test                 ASIO 类型转换核自检
asio_bridge --capture-test              进程回环采集自检(渲染→自采比对)
asio_bridge --limiter-test              端点限幅器位置实测
asio_bridge --crash-test                故意崩溃, 验证崩溃自愈链路(诊断)
asio_bridge --respawn <ms>              (内部)崩溃自愈拉起前等待旧实例退出

Ctrl+C 停止; 崩溃时自动重启(5 分钟内最多 5 次, 防死循环),
重启记录见 exe 同目录 restarts.log。

第六章 Web 控制台
================================================================================
地址: http://127.0.0.1:3999
风格: 复古金属仪表(拉丝金属表头 + 电子管指示灯 + 机械按键 + 导弹发射键)

--------------------------------------------------------------------------------
6.1 遥测面板(TELEMETRY)
--------------------------------------------------------------------------------
三块复古正圆指针表头:
  - 峰值 PEAK     (实时峰值, 0~1.0)
  - 水位 WATERMARK(环形缓冲水位, 目标线为琥珀)
  - 链路延迟 LATENCY(端到端毫秒)
下方副栏(chips)显示: 目标/采集 Hz/ASIO Hz/缓冲/运行时长/
  实测输入 Hz/实测输出 Hz/锁频(±ppm)/目标进程/欠载/漂移。

--------------------------------------------------------------------------------
6.2 水位历史(WATERMARK HISTORY)
--------------------------------------------------------------------------------
最近 10 分钟的水位曲线(每 2 秒一个采样点)。
  - 黄色曲线 = 水位, 琥珀虚线 = 目标水位
  - Y 轴自动缩放(峰值上浮 15% 对齐 1024)

--------------------------------------------------------------------------------
6.3 系统状态(SYSTEM STATUS)
--------------------------------------------------------------------------------
5 个电子管指示灯: 采样率链一致 / 锁频锁定 / 无欠载 / 无削波 / 时钟漂移<100ppm。

--------------------------------------------------------------------------------
6.4 300B 频谱(SPECTRUM · 谐波叠加)
--------------------------------------------------------------------------------
实时线性频谱(0 ~ Nyquist), 纵轴 -120 ~ 0 dBFS(响度)。
  - 暖黄波浪 = 音乐原始频谱
  - 青色波浪 = 新增谐波(300B 染色产生的残差, 叠加在原始上)
  - 谐波增益滑块(+0~+60dB, 默认 0): 放大青色波浪, 便于观察谐波覆盖频率。
  - 谐波默认显示真实比例(放大过多时用增益滑块临时放大查看)。

--------------------------------------------------------------------------------
6.5 控制台面板(CONTROL DECK)
--------------------------------------------------------------------------------
6.5.1 输出设备(第一行)
  下拉框列出系统全部渲染端点, 每项标注后端类型:
    [ASIO]  = 有匹配的 ASIO 驱动 → 走 ASIO 输出
    [WASAPI] = 无 ASIO → 走 WASAPI 独占输出
  「自动(默认 ASIO)」= 使用 --driver 指定的 ASIO 驱动。
  选择设备后桥自动重建链路; 「刷新」按钮重新扫描设备。

6.5.2 水位下限
  4×/6×/8×/12×/16×: 环形缓冲目标水位倍数(默认 8×)。
  越大越稳但延迟越高; 调低可获得更低延迟(欠载风险上升)。

6.5.3 TPDF 抖动 / 直通模式
  TPDF 抖动: float→整数转换时注入 ±1LSB 三角抖动, 降低量化失真(默认开)。
  直通模式: 停用重采样, ratio 恒 1.0 逐位直通(漂移由环形缓冲吸收)。

6.5.4 重采样质量
  线性低延迟(0 taps) / sinc 高精度(32 taps, 默认)。
  sinc 档对时钟漂移级重采样 THD 更低, 听感更干净。

6.5.5 300B 染色 + 暖度
  300B 染色: FET 平方律电子管暖声模拟(开/关)。
  暖度: 0~100%(默认 30%), 染色量。开染色后频谱面板能看到新增谐波。

6.5.6 厚度与宽度
  「厚度与宽度」开关: 把 300B 染色产生的谐波做预延时+带限后再混回,
  产生「加厚/加宽」的空间感(干信号保持不动)。
  厚度: 2~100ms 滑动杆(纯左右滑动, 凭听觉调节, 无数字显示)。
  宽度: 四档左右声道固定差(哈斯效应):
    关闭 0ms / 俱乐部 5ms / 音乐厅 12ms / 太和殿 25ms
  高低切: 低切 160Hz(-36dB/oct) + 高切 8kHz(-12dB/oct), 只作用于谐波层。

6.5.7 火箭推进器
  「火箭推进器」开关 + 增益滑块(0~100% = 0~+18dB):
  放大「厚度与宽度」的延时谐波层, 让厚度/宽度效果更明显。
  默认 0%(不放大); 谐波本就很小, 放大后效果会立刻变突出。

6.5.8 ASIO Bridge 开关(红色导弹发射键)
  红色 = 桥接中(目标端点被静音, 消除双重声);
  灰色 = 已停止(系统音量恢复)。
  点击切换, 相当于一键停桥/开桥。

6.5.9 重置统计
  把所有计数(写/读/欠载/丢弃/峰值/漂移/历史)归零。

--------------------------------------------------------------------------------
6.6 顶部 BRIDGE 表头
--------------------------------------------------------------------------------
左侧为「文超工作室」铭牌(瘦金体/楷体书法风),
右侧 3 个电子管: PWR(电源) / ASIO(输出激活) / CAPTURE(采集活跃)。

================================================================================
第七章 输出设备与后端(ASIO / WASAPI 独占)
================================================================================
桥启动时自动扫描:
  - 枚举系统全部「活动渲染端点」(WASAPI)
  - 枚举 ASIO 驱动(注册表 HKLM\SOFTWARE\ASIO)
  - 按名字匹配自动判定每个设备的后端类型:
      匹配到 ASIO 驱动 → 该设备走 ASIO 输出
      未匹配 → 走 WASAPI 独占输出(叠加完整 DSP 链)

控制台「输出设备」下拉框展示全部设备及后端类型, 选择即切换。

当前系统的典型情况:
  - RME MADIface / Realtek 板载 → 匹配到 ASIO, 走 ASIO
  - HDMI/DP 显示音频、无 ASIO 的 USB DAC/耳机 → 走 WASAPI 独占

注意:
  - WASAPI 独占会锁定设备, 若该设备正被其他程序使用会提示
    "设备被占用"(DEVICE_IN_USE), 需先释放。
  - 独占模式格式按设备混音格式协商, 自动回退 float32/int16/int32
    × 48k/44.1k/32k。

================================================================================
第八章 音色与效果
================================================================================
信号链(在输出缓冲上逐样本处理):
  原始 x → 300B 平方律饱和(暖度) → y
  谐波 = y - x
  若「厚度与宽度」开: 谐波 → 预延时(2~100ms, 左右声道加宽度差)
       → 低切160Hz(-36dB/oct) → 高切8kHz(-12dB/oct) → 火箭推进器增益
  → 混回干信号 x

关键语义:
  - 干信号永远不动(bit-perfect 于 DSP 关闭时)
  - 300B 染色关 → 无谐波 → 厚度/宽度/火箭推进器自动失效
  - 所有音色都是「可选调色」: 全部关闭即直通

推荐试听组合:
  - 轻暖: 300B 染色 30% + 暖度 30%
  - 明显厚度: 300B 30% + 厚度 60ms + 音乐厅
  - 抓耳宽声像: 300B 50% + 厚度 60ms + 太和殿 + 火箭推进器 +18dB

  asio_bridge --resampler-test   重采样器直通精度/漂移/饥饿

  asio_bridge --capture-test     渲染 997Hz → 按 PID 回采比对(验证进程回环)
  asio_bridge --limiter-test     端点限幅器位置实测(需 float32 端点)

第十一章 配置文件(asio_bridge.cfg)
================================================================================
位置: exe 同目录(build\Release\asio_bridge.cfg), 每 5 秒自动保存。
内容(可用记事本改, 桥重启后生效):
  tube_on=0             # 300B 染色开关
  tube_warmth=0.3000    # 暖度 0~1
  thickness_on=0        # 厚度与宽度开关
  thickness_delay=20.0  # 厚度(预延时) 2~100ms
  thickness_width=0     # 宽度档 0~3
  booster_on=0          # 火箭推进器开关
  booster_db=12.0       # 湿增益 dB 0~18
  passthrough=0         # 直通模式
  floor=8               # 水位下限倍数
  src_taps=32           # 重采样档 0/32
  dither=1              # TPDF 抖动

第十二章 常见问题
================================================================================
Q: 桥启动后没声音?
   A: 等 10~20 秒自动锁定目标进程(控制台可见 PID)。
      确认输出设备已选对(默认 ASIO; 无 ASIO 设备走 WASAPI 独占)。
      确认目标应用音量 100%。

Q: 换了声卡没声音?
   A: 控制台「输出设备」下拉选择新设备, 或确认它在 /api/devices 里的
      后端类型。有 ASIO → 走 ASIO; 无 → WASAPI 独占。

Q: WASAPI 独占提示设备被占用?
   A: 该设备正被其他程序使用(独占模式锁设备)。关闭占用程序后重试。

Q: 欠载(underrun)一直增加?
   A: 把水位下限调高(8×→12×/16×), 或换 sinc 重采样。

Q: 双重声(原声+桥副本)?
   A: 桥会自动静音目标端点; 若用 --no-mute 启动则会出现, 去掉该参数。

Q: 打开控制台页面是空白的?
   A: 确认桥在运行且端口 3999 未被占用(改端口需改源码)。

Q: 音色(300B/厚度/火箭)没效果?
   A: 300B 染色必须开(它产生谐波); 暖度调高; 厚度/宽度/火箭才有作用对象。

Q: 想低延迟?
   A: --buffer 128/64(ASIO), 水位下限 4×~6×, 但欠载风险上升。

第十三章 故障排查与日志
================================================================================
日志: --log <文件> 指定; 自动任务默认 %USERPROFILE%\asio_bridge.log。
崩溃日志: exe 同目录 crash.log(含线程身份/位置/模块偏移)。
重启记录: exe 同目录 restarts.log(300 秒窗口最多 5 次)。

关键日志含义:
  [采集] 48000 Hz / 2 通道 / 32 bit (float32)  采集端格式
  [ASIO] 驱动: hdspfire 版本: 1                ASIO 驱动加载
  [ASIO] 48000 Hz / 2 通道 / 缓冲 528 帧 / 类型 Int24LSB  ASIO 会话参数
  == 桥接运行中: ... ==                      链路建立成功
  输出后端初始化失败: ...(2 秒后重试)          输出端失败, 自动重试
  [静音] 已静音目标进程 N 所在 1 个端点         消除双重声生效
  [快排] 水位超 2.5× 目标, 丢弃陈旧采样 X       启动预滚清理(正常)

错误码速查:
  0x8889000A  DEVICE_IN_USE       设备被独占占用(释放后重试)
  0x88890008  UNSUPPORTED_FORMAT  格式不支持(自动回退其它格式)
  0x88890016  BUFFER_SIZE_NOT_ALIGNED 缓冲未对齐(已自动重试)
  0x88890004  DEVICE_INVALIDATED  设备失效(自动重建)
  0x80004002  E_NOINTERFACE       RME 需 STA 公寓(代码已处理)
  0xC0000005  访问违例            驱动掉线/野指针(崩溃自愈已兜底)
