================================================================================
                     ASIO 桥 项目详细介绍
     应用 PCM → Windows 11 进程回环（按 PID 旁路）→ RME MADIface ASIO → 专业声卡/DAC
================================================================================
版本: v2.0   日期: 2026-08-21   平台: Windows 11 22H2+ x64 + VS2022 + ASIO SDK 2.3

--------------------------------------------------------------------------------
一、项目目标
--------------------------------------------------------------------------------
让第三方现成应用（Apple Music、浏览器、播放器、游戏等）的 PCM 音频绕过
Windows 音频引擎的混音、重采样与 APO 音效处理，直接进入 RME MADIface ASIO
驱动，输出到 专业声卡/DAC 解码器，实现 bit-perfect 播放。

核心思路（v2）：不再使用虚拟声卡截流，而是用 Windows 11 原生「进程回环
（Process Loopback）」按 PID 旁路监听目标进程「混音后」的渲染流——
免虚拟声卡、免第三方驱动、不占麦克风、与目标应用输出到哪个设备无关。

为什么需要桥：第三方应用只支持 WASAPI 共享模式输出；Windows 引擎会对所有
共享流做混音/重采样/音效；而 专业声卡/DAC 的 WDM 端点只有 16bit（多通道
固定格式），Hi-Res 能力只有 MADIface ASIO 驱动才完整提供。

--------------------------------------------------------------------------------
二、总体架构与数据流
--------------------------------------------------------------------------------
ASCII 示意:

   目标应用（播放器 / 浏览器 / 游戏）
     │  WASAPI 共享渲染（float32）
     ▼
   Windows 音频引擎（audiodg）
     │  VAD\Process_Loopback 按 PID 旁路取流
     │  取点位置：会话处理之后、终点主音量之前（数值实验实测）
     ▼
   ┌────────────────────────── asio_bridge.exe ───────────────────────────┐
   │  采集线程(独立 MTA, SEH 防护) ──float32──▶ 环形缓冲(SPSC 无锁)        │
   │                                                    │                │
   │  速率锁(双环) + 分数重采样 + TPDF 抖动 + 300B 染色   │                │
   │                                                    ▼                │
   │                            ASIO 回调 bufferSwitchTimeInfo            │
   │                                │ 转 Int32LSB 写驱动缓冲               │
   └────────────────────────────────┼──────────────────────────────────────┘
                                    ▼
                  MADIface ASIO 驱动 (madiface_asio_amd.dll)
                                    │
                                    ▼
                           专业声卡/DAC DAC ──▶ 耳机/音箱

被绕过的部分: 系统音频引擎 audiodg 的混音/重采样/APO 不参与本链路。

三、系统组成详解
--------------------------------------------------------------------------------
3.1 进程回环采集 WasapiProcessCapture (src/wasapi_process_capture.*)
    - 按 PID 激活回环客户端：AUDIOCLIENT_ACTIVATION_TYPE_PROCESS_LOOPBACK +
      PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE（含子进程树），
      目标设备名 VIRTUAL_AUDIO_DEVICE_PROCESS_LOOPBACK。
    - 必须用外层 AUDIOCLIENT_ACTIVATION_PARAMS 包装（裸的
      AUDIOCLIENT_PROCESS_LOOPBACK_PARAMS 会得到 E_INVALIDARG）。
    - 激活回调 handler 必须实现 IAgileObject（Win11 mmdevapi 会 QI 它，
      缺省会错误映射为 E_OUTOFMEMORY 0x8007000E）。
    - 格式策略：先试客户端自身 GetMixFormat；本机恒 E_NOTIMPL → 退到
      GetTargetMixFormat（找目标进程最响会话所在端点的真实引擎混音格式，
      免 AUTOCONVERTPCM，位更纯）；再不行回退 16bit/2ch/44100 + AUTOCONVERTPCM。
    - 任意 PCM/float 格式统一转换 float32（16/24/32bit、float32 全覆盖）。
    - 事件驱动 GetNextPacketSize/GetBuffer 循环，200ms 超时轮询兼作失效检测；
      SEH 兜底捕获设备重启期间的野指针访问违例。

3.2 会话发现 FindActiveAudioPid
    - 枚举全部活动渲染端点的音频会话，用 ISimpleAudioMeter 峰值找「最响」进程。
    - 自动排除桥自身 PID：进程回环会让引擎把桥注册为「回声会话」，其峰值等于
      被采内容——不排除会锁死自己。
    - 支持 preferredSubstr 优先匹配进程名子串。
    - 必须在 MTA 线程执行：桥主线程是 ASIO 的 STA，直接枚举会 RPC_E_CHANGED_MODE
      静默返回 0（进程回环自动发现一直失效的根因），RunComOnMta 委托 MTA 工作线程。

3.3 环形缓冲 RingBuffer (src/ring_buffer.h)
    - 单生产者(采集线程)/单消费者(ASIO 回调)无锁环形缓冲，容量 131072 采样(≈3s@44.1k)。
    - 写入/读取下标分占独立 cache line（alignas(64)），避免伪共享。
    - 生产者溢出自动截断；消费者水位过高时丢弃多余采样（漂移校正）。

3.4 时钟速率锁 RateLock (src/rate_lock.h)
    - 双环前馈：从投递/消费回调的 (QPC, 累计采样) 时间戳对，最小二乘测
      输入/输出设备真实速率；ratioBase = inHz / outHz。
    - 断档检测：进程回环交付易受暂停/恢复突发污染（曾测出 -710ppm 假读数），
      60 秒短窗 + 500ms 断档截断 + 15 秒清洁段要求，秒级收敛。
    - ratioBase 钳制到 [0.999, 1.001]。

3.5 分数重采样 FractionalResampler (src/resampler.h)
    - 双通道交错 float32，按「帧」插值（L 只在 L 间、R 只在 R 间）。
    - 质量档：0=线性（低延迟），32=32-tap 汉宁窗 sinc（高精度，默认）。
    - 256 档预计算系数表 + 相位行间线性插值，热循环零超越函数。
    - wantIn()/process() 精确对账，sinc 保留 16 帧回看历史；饥饿时保持末帧、
      游标冻结，绝不空转。

3.6 水位闭环（主循环）
    - 平滑水位（约 20 秒时间常数）只在速率锁基值上做微调：
      ratio = base + err×5e-7，误差分档限幅（稳态 0.0003 / 中等 0.001 / 大 0.004）。
    - 自适应 v2：新欠载硬触发 +4；每 10 秒窗口波谷 < 半目标预判 +4；
      连续 3 窗口波谷 > 90% 目标回落 -4；下限可由控制台调（默认 8×缓冲）。
    - 快排：水位超 2.5× 目标直接丢弃陈旧预滚帧至 1.5×。
    - 直通模式（--passthrough）：ratio 恒 1.0 逐位直通，漂移交给环形缓冲，
      预填充加大到 16384 采样（~186ms），漂移 ±1.1 采样/秒 ≈ 4 小时余量。

3.7 输出端 AsioRender (src/asio_render.*)
    - 集成 Steinberg ASIO SDK 2.3（vendored 于 third_party/）。
    - 流程: loadAsioDriver → ASIOInit → ASIOGetChannels → ASIOSetSampleRate
            → ASIOGetBufferSize → ASIOCreateBuffers → ASIOStart。
    - 采样率跟随采集端协商速率；RME 设备时钟随之切换。
    - float32 → 驱动原生类型（Int32LSB/Int24LSB/Int16LSB/Float32/64 均已实现）。
    - TPDF 抖动（默认开）：float→整数转换注入 ±1LSB 三角抖动，消除量化相关失真。
    - 欠载恢复包交叉淡化接缝（fadeInFrames=32）。
    - 回调表/驱动信息作为成员存储（RME 只存指针不拷贝，放栈上会 rip=0 崩溃）。

3.8 内嵌 Web 控制台 (src/web_console.*)
    - http://127.0.0.1:3999，纯 socket 线程、零 COM，只读共享原子量。
    - 提供：实时水位示波、速率锁读数、链路 LED、水位下限、TPDF 抖动、
      直通/重采样切换、300B 染色与暖度、重置统计、目标进程 PID 等。

3.9 tap→redirect（端点静音）MuteTargetEndpoints/RestoreEndpointMutes
    - 进程回环是旁路监听，目标应用原声仍到扬声器造成双重声。
    - 数值自检证明：回环取点在「会话静音之后、终点主音量之前」——
      静音目标进程（含进程树）所在渲染端点的终点主音量，既消除双重声、
      又完全不影响捕获；ASIO 输出不走 WDM 终点音量，同样不受影响。
    - 重建/退出时自动恢复原静音态（外部预静音保持不动）。

四、关键技术问题与解决（攻关实录）
--------------------------------------------------------------------------------
4.1 RME MADIface ASIO 加载失败 E_NOINTERFACE (0x80004002)
    现象: CoCreateInstance(riid=CLSID) 返回 E_NOINTERFACE，PowerShell 里
          Activator(riid=IUnknown) 却成功。
    根因: RME 的 COM 对象(ThreadingModel=Apartment) 只在 STA 公寓暴露 ASIO 接口。
    解决: 主线程 CoInitializeEx(COINIT_APARTMENTTHREADED)；采集/发现/静音的 COM
          全部移入各自 MTA 线程自管，避免跨公寓调用。

4.2 桥运行数秒即崩溃（0xC0000005）
    现象: 引入速率轮询后启动 4~5 秒必崩。
    根因: 主 STA 线程上的阻塞式 COM 调用(GetMixFormat RPC)饿死了 MADIface 的
          STA 回调机制，驱动内部崩溃带走进程。
    解决: 主 STA 线程只做 Sleep/事件等待/统计打印，绝不做阻塞式 COM 调用；
          发现/枚举经 RunComOnMta 委托 MTA 工作线程。

4.3 进程回环自动发现一直失效（静默返回 0）
    现象: 在 STA 主线程上枚举会话总得到空结果。
    根因: 非 MTA 线程做 MTA COM 枚举得到 RPC_E_CHANGED_MODE，被静默吞掉。
    解决: RunComOnMta 包装：当前线程非 MTA 时开 MTA 工作线程执行并等待结果。

4.4 进程回环 GetMixFormat 恒 E_NOTIMPL
    现象: 回环客户端自身的 GetMixFormat 在目标无活动流时返回 E_NOTIMPL。
    解决: 退到目标端点真实引擎混音格式（GetTargetMixFormat），再不行回退
          16/2/44100 + AUTOCONVERTPCM。

4.5 速率锁被暂停/恢复突发污染（假读数 -710ppm）
    现象: 目标应用暂停/恢复瞬间引擎突发补送，窗口斜率被污染。
    解决: 断档截断——回归只用断档后的清洁段，要求清洁段 ≥15 秒；60 秒短窗
          快速淘汰脏数据（±16ppm 但秒级收敛，远好于被污染的 ±700ppm）。

4.6 驱动级空指针崩溃无法进程内拦截
    现象: RME 掉线清空自身函数表，驱动线程调用空指针带走进程
          (crash.log: madiface_asio_amd.dll+0x4385, rip=0)。
    解决: 崩溃自愈——未处理异常过滤器 crashFilter 写 crash.log（含线程身份 +
          TLS 面包屑 + 模块偏移），并拉起新实例接管；restarts.log 300 秒窗口
          最多 5 次防死循环。--respawn 内部参数让新实例等旧实例退出后再启动。

五、使用指南
--------------------------------------------------------------------------------
5.1 构建（需要 VS2022 + CMake ≥3.20）
    cmake -B build -S .
    cmake --build build --config Release
    产物: build\Release\asio_bridge.exe

5.2 运行
    asio_bridge                         桥接模式(自动发现并锁定最响渲染进程)
    asio_bridge --list                  列出 ASIO 驱动
    asio_bridge --tone [--rate 44100]   1kHz 正弦测试(验证 ASIO 链路)
    asio_bridge --driver <名字>         指定 ASIO 驱动(默认 ASIO MADIface USB)
    asio_bridge --buffer <帧数>         ASIO 缓冲帧数(低延迟可试 128/64)
    asio_bridge --log <文件>            输出追加写入日志(后台/自启用)
    asio_bridge --no-dither             关闭 TPDF 抖动(默认开启)
    asio_bridge --passthrough           直通模式(停用重采样,ratio 恒 1.0)
    asio_bridge --no-mute               诊断: 跳过端点静音(可能出现双重声)
    asio_bridge --resampler-test        重采样器正弦离线自检
    asio_bridge --pll-test              速率锁+水位闭环联合仿真自检
    asio_bridge --capture-test          采集自检(渲染→按 PID 回环自采比对)
    asio_bridge --limiter-test          端点限幅器位置实测
    asio_bridge --tube-test             300B 染色数值自检
    asio_bridge --conv-test             ASIO 类型转换核自检
    asio_bridge --crash-test            故意崩溃验证自愈链路(诊断用)
    Ctrl+C 停止；崩溃自动重启(5 分钟内最多 5 次)，详见 restarts.log

5.3 日常使用流程
    1) 启动 Bridge（.\\build\\Release\\asio_bridge.exe）。
    2) 播放任意应用音频（首次运行请确认该应用有输出设备可用）。
    3) Bridge 10~20 秒内自动锁定该进程（控制台「目标进程」可见 PID 与活跃态）。
    4) 控制台 http://127.0.0.1:3999 提供水位下限、抖动、直通、染色、
       重建链路、重置统计等控制。
    5) 想固定某个应用：目标会自动跟随「最响的渲染进程」，切歌/暂停自动跟随。

5.4 开机自启
    pwsh -File tools\install_autostart.ps1          安装计划任务
    pwsh -File tools\install_autostart.ps1 -Remove  卸载
    任务名 "ASIO Bridge"：用户登录触发、隐藏窗口、最高权限、
    失败自动重启 3 次(间隔 1 分钟)、防重复实例。
    日志: %USERPROFILE%\asio_bridge.log

六、性能与限制
--------------------------------------------------------------------------------
- 链路延迟 ≈ 采集包周期(~10ms) + 环形驻留 + ASIO 设备延迟 + 重采样器固有延迟。
- 时钟漂移: 目标应用引擎时钟与 RME 硬件时钟独立，ppm 级漂移由速率锁 +
  分数重采样 + 水位闭环吸收，长时间聆听平滑无滑移。
- 需要 Windows 11 22H2+（进程回环 API）。
- 端点静音作用域为整端点：该端点上其他 WDM 声音（系统提示音等）一并静音。
- 目标应用暂停时回环无数据包，短暂欠载由自适应水位吸收。
- ASIO 驱动被 DAW 独占时桥无法启动（自动重试）。
- bit-perfect 前提: 内容采样率 = 引擎混音格式 + 应用音量 100% + 端点无 APO。
