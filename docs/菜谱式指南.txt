================================================================================
               高保真音频直通 ASIO 桥 · 菜谱式指南（纯文本版）
================================================================================

本菜名: 原味直通牛（Apple Music -> 专业声卡/DAC，不加系统调味料）
口味特点: bit-perfect（比特透明）、零欠载、免虚拟声卡、按 PID 自动跟随目标
难度: ★★★★☆（需要 VS2022 + C++，全部坑已标注解法）
耗时: 首次约 2~4 小时（含调试）；照抄本菜谱约 1 小时
总延迟: 约 20~120ms（听音乐无感知，看视频请走系统路径）

================================================================================
第一章 · 成品清单（已确认的技术成果）
================================================================================

 1. 进程回环直通桥(v2): Win11 原生按 PID 旁路采集 -> 环形缓冲 -> 速率锁 +
    分数重采样 -> MADIface ASIO 直出
 2. 免虚拟声卡: 不再装 VB-CABLE；目标输出到哪个设备都行，桥按「最响渲染
    进程」自动锁定
 3. STA 公寓定律: RME 的 ASIO COM 对象(ThreadingModel=Apartment) 只在 STA
    线程暴露接口，MTA 下返回 E_NOINTERFACE
 4. ASIO 宿主禁律: 绝不能在 ASIO 的 STA 主线程做阻塞式 COM 调用——会饿死
    MADIface 回调，进程数秒内崩溃
 5. 跨公寓枚举修复: 非 MTA 线程枚举会话会 RPC_E_CHANGED_MODE 静默返回 0，
    RunComOnMta 委托 MTA 线程才修好自动发现
 6. tap→redirect 取点实证: 回环取点在「会话静音之后、终点主音量之前」——
    静音目标端点主音量消除双重声且不影响捕获
 7. 回环格式回退链: 回环客户端 GetMixFormat 恒 E_NOTIMPL -> 退目标端点混音
    格式 -> 再退 16/2/44100+AUTOCONVERTPCM
 8. 双环速率锁 + 分数重采样: QPC 成对时间戳最小二乘测两时钟速率，sinc
    重采样吸收 ppm 漂移，长时间平滑无滑移
 9. 崩溃自愈: 驱动级空指针崩溃进程内无法拦截 -> crashFilter 拉起新实例，
    300 秒窗口最多 5 次防死循环
10. 内嵌 Web 控制台: http://127.0.0.1:3999 复古仪表风，水位/速率锁/链路
    LED/染色/直通全可调

第三章 · 原理（这道菜为什么这么做）
================================================================================

3.1 完整数据流（成品上桌路径）

  目标应用 --WASAPI共享渲染(float32)--> Windows音频引擎(audiodg)
                                            | VAD\Process_Loopback 按 PID 旁路
                                            v
  +---------------------- asio_bridge.exe ----------------------+
  | 采集线程(MTA+SEH) --float32--> 环形缓冲(SPSC无锁)             |
  |                                         | 速率锁+重采样      |
  | 主线程(STA: ASIO会话) <-- 统计/看门狗/自适应水位              |
  |                                         v                    |
  |                  ASIO回调 bufferSwitchTimeInfo               |
  |                  float32 -> Int32LSB (+TPDF抖动, 可选染色)   |
  +-------------------------------|------------------------------+
                                  v
                   MADIface ASIO 驱动(madiface_asio_amd.dll)
                                  v
                     专业声卡/DAC DAC --> 耳机/音箱

3.2 三个"为什么"

  为什么用进程回环而不是虚拟声卡？封闭应用只支持 WASAPI 共享输出，装不了
  ASIO 插件。v1 用 VB-CABLE 截流但固定 44.1k 且需装驱动；v2 直接用 Win11
  原生按 PID 回环旁路，免驱动、免虚拟声卡、跟设备无关。

  为什么不直接用系统路径到 RME？系统路径必然经过 audiodg 的混音/重采样/
  APO，且 RME WDM 端点是 16bit 截断；MADIface ASIO 才是全位深/全采样率通道。

  为什么需要环形缓冲 + 速率锁？采集时钟与 ASIO 硬件时钟独立，ppm 级漂移；
  环形缓冲吸收抖动，速率锁 + 分数重采样让重采样比精确追踪两时钟速率。

3.3 bit-perfect 的成立条件（验收标准）

  1. 内容采样率 = 引擎混音格式（float32 全链路位透明）
  2. 应用音量 = 100%
  3. 目标端点无 APO / 无增强
  4. 直通模式(--passthrough)下 ratio 恒 1.0 逐位直通

第四章 · 制作步骤（复现指南）
================================================================================

步骤 1 备料: 无需装虚拟声卡；确认系统 Win11 22H2+ 且装了 RME MADIface 驱动。

步骤 2 搭工程: git 或拷贝仓库至 E:\Harness\asio-bridge（third_party 已含 SDK）。

步骤 3 编译:
    cmake -B build -S .
    cmake --build build --config Release
    （或命令行重建: cmd /c tools\rebuild.cmd）

步骤 4 首测(ASIO 链路验证):
    .\build\Release\asio_bridge.exe --tone --rate 44100
    听到 1kHz 正弦、专业声卡/DAC 屏幕显示 44.1 -> 链路 OK，Ctrl+C 停止。

步骤 5 全链路测试:
    终端1: .\build\Release\asio_bridge.exe
    终端2: 播放任意音频
    观察桥日志：目标 PID 出现、峰值 > 0、欠载=0 为佳。

步骤 6 数值自检(先测后上线):
    --resampler-test  --pll-test  --tube-test  --conv-test
    --capture-test    --limiter-test

步骤 7 开机自启(无窗口):
    pwsh -File tools\install_autostart.ps1           安装
    pwsh -File tools\install_autostart.ps1 -Remove   卸载
    日志: %USERPROFILE%\asio_bridge.log

步骤 8 日常使用:
    启动桥 -> 播放任意音频 -> 10~20 秒自动锁定目标 -> 控制台看状态。

第五章 · 火候与调味（参数对照表 + 音质提升思路）
================================================================================

5.1 调参表（低延迟 <-> 高稳定）

  ASIO 缓冲帧数     --buffer            128(驱动锁 min=max)   越小延迟越低
  水位下限倍数      控制台/cfg floor     8×缓冲                越大越稳越延迟
  重采样质量档      控制台/cfg src_taps  32=sinc(默认)0=线性   sinc 高精度
  直通模式          --passthrough        关闭(默认)            开则 ratio 恒 1.0
  TPDF 抖动         --no-dither          开(默认)              关更纯净
  300B 染色         控制台/cfg warmth    0.3                   0=干净 1=暖

5.2 提升音质的思路（进阶菜谱）

  已做到: 绕开混音/APO、float32 全链路、双环速率锁+分数重采样平滑无滑移。
  可再做: 多采样率自适应、隔离播放链、更高位深/DSD、ASIO 双向时钟同步。

5.3 音质自检清单
  [ ] 专业声卡/DAC 屏幕速率 = 内容速率
  [ ] 桥日志 欠载=0、峰值<1.0
  [ ] 应用音量 100%
  [ ] 目标端点无增强
  [ ] 直通模式下 ratio 恒 1.0

第六章 · 常见翻车点（全部实测踩过，附解法）
================================================================================

  E_NOINTERFACE(0x80004002)            RME COM 只在 STA 暴露 -> 主线程 STA
  运行 4~5 秒必崩(0xC0000005)          STA 主线程阻塞 COM -> 主线程零 COM
  自动发现失效(静默空结果)             RPC_E_CHANGED_MODE -> RunComOnMta
  回环激活 E_OUTOFMEMORY(0x8007000E)   handler 缺 IAgileObject -> 补上
  回环 GetMixFormat E_NOTIMPL          目标无活动流 -> 退目标端点格式
  速率锁读数突跳 ±700ppm               暂停/恢复污染 -> 60s 短窗+断档截断
  设备重启采集线程崩溃                 野指针 COM -> SEH 兜底+设备事件重建
  双重声                               原声+副本 -> 自动静音目标端点主音量
  开机弹 cmd 窗口                      计划任务直启 -> wscript+VBS 隐藏链
  ASIO 被 DAW 占用起不来               MADIface 单客户端 -> 先停桥再用 DAW
