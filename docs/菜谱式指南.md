# 高保真音频直通 ASIO 桥 · 菜谱式指南

> **本菜名**：原味直通牛（Apple Music → 专业声卡/DAC，不加系统调味料）
> **口味特点**：bit-perfect（比特透明）、零欠载、免虚拟声卡、按 PID 自动跟随目标
> **难度**：★★★★☆（需要 VS2022 + C++，全部坑已标注解法）
> **耗时**：首次约 2~4 小时（含调试）；照抄本菜谱约 1 小时
> **总延迟**：约 20~120ms（听音乐无感知，看视频请走系统路径）

## 第一章 · 成品清单（已确认的技术成果）

| # | 成果 | 一句话说明 |
|---|------|-----------|
| 1 | **进程回环直通桥（v2）** | Win11 原生按 PID 旁路采集 → 环形缓冲 → 速率锁 + 分数重采样 → MADIface ASIO 直出 |
| 2 | **免虚拟声卡** | 不再装 VB-CABLE；目标应用输出到哪个设备都行，桥按「最响渲染进程」自动锁定 |
| 3 | **STA 公寓定律（关键发现）** | RME 的 ASIO COM 对象(ThreadingModel=Apartment) **只在 STA 线程暴露接口**，MTA 下返回 E_NOINTERFACE |
| 4 | **ASIO 宿主禁律（崩溃根因）** | 绝不能在 ASIO 的 STA 主线程做阻塞式 COM 调用——会饿死 MADIface 回调，进程数秒内崩溃 |
| 5 | **跨公寓枚举修复** | 非 MTA 线程枚举会话会 RPC_E_CHANGED_MODE 静默返回 0，RunComOnMta 委托 MTA 线程才修好自动发现 |
| 6 | **tap→redirect 取点实证** | 回环取点在「会话静音之后、终点主音量之前」——静音目标端点主音量消除双重声且不影响捕获 |
| 7 | **回环格式回退链** | 回环客户端 GetMixFormat 恒 E_NOTIMPL → 退目标端点混音格式 → 再退 16/2/44100+AUTOCONVERTPCM |
| 8 | **双环速率锁 + 分数重采样** | QPC 成对时间戳最小二乘测两时钟速率，sinc 重采样吸收 ppm 漂移，长时间平滑无滑移 |
| 9 | **崩溃自愈** | 驱动级空指针崩溃进程内无法拦截 → crashFilter 拉起新实例，300 秒窗口最多 5 次防死循环 |
| 10 | **内嵌 Web 控制台** | http://127.0.0.1:3999 复古仪表风，水位示波/速率锁/链路 LED/染色/直通全可调 |

## 第三章 · 原理（这道菜为什么这么做）

### 3.1 完整数据流（成品上桌路径）

```
目标应用 ──WASAPI 共享渲染(float32)──▶ Windows 音频引擎(audiodg)
                                              │ VAD\Process_Loopback 按 PID 旁路
                                              ▼
┌────────────────── asio_bridge.exe ──────────────────────┐
│ 采集线程(MTA+SEH) ──float32──▶ 环形缓冲(SPSC无锁)        │
│                                       │ 速率锁+重采样    │
│ 主线程(STA: ASIO会话) ◀──统计/看门狗/自适应水位           │
│                                       ▼                  │
│                ASIO回调 bufferSwitchTimeInfo             │
│                float32 → Int32LSB (+TPDF抖动, 可选染色)  │
└──────────────────────────────┬───────────────────────────┘
                               ▼
                   MADIface ASIO 驱动(madiface_asio_amd.dll)
                               ▼
                     专业声卡/DAC DAC ──▶ 耳机/音箱
```

### 3.2 三个"为什么"

**为什么用进程回环而不是虚拟声卡？** 封闭应用（Apple Music、浏览器）只支持 WASAPI 共享输出，你无法给它装 ASIO 插件。v1 用 VB-CABLE 截流，但发现它固定 44.1k 且需装驱动；v2 直接用 Win11 原生的按 PID 回环旁路，免驱动、免虚拟声卡、跟设备无关。

**为什么不直接用系统路径到 RME？** 系统路径必然经过 audiodg 的混音/重采样/APO，且 RME 的 WDM 端点是 16bit 截断；MADIface ASIO 驱动才是唯一支持全位深/全采样率的通道。

**为什么桥需要环形缓冲 + 速率锁？** 采集时钟（引擎）与 ASIO 时钟（RME 硬件）独立运行，存在 ppm 级漂移；环形缓冲吸收调度抖动，速率锁 + 分数重采样让重采样比精确追踪两时钟速率，长时间聆听不产生采样滑移。

### 3.3 bit-perfect 的成立条件（验收标准）

1. 内容采样率 = 引擎混音格式（回环按目标端点混音格式采集，float32 全链路位透明）
2. 应用音量 = 100%（引擎才会原样传递）
3. 目标端点无 APO / 无「音频增强」
4. 直通模式（`--passthrough`）下 ratio 恒 1.0，逐位直通

满足全部条件时：全链路仅发生 float32 格式转换（≤24bit 无损），零重采样、零量化损失。

## 第四章 · 制作步骤（复现指南）

### 步骤 1：备料
```powershell
# 无需装任何虚拟声卡；确认系统是 Windows 11 22H2+，装了 RME MADIface 驱动即可
```

### 步骤 2：搭工程
```powershell
git 或拷贝本仓库至 E:\Harness\asio-bridge（third_party 已含 ASIO SDK 2.3）
```

### 步骤 3：编译
```powershell
cmake -B build -S .          # VS2022 自带 CMake
cmake --build build --config Release
# 或命令行重建(不依赖 CMake): cmd /c tools\rebuild.cmd
```

### 步骤 4：首测（ASIO 链路验证）
```powershell
.\build\Release\asio_bridge.exe --tone --rate 44100
# 听到 1kHz 正弦、专业声卡/DAC 屏幕显示 44.1 → ASIO 链路 OK，Ctrl+C 停止
```

### 步骤 5：全链路测试
```powershell
# 终端 1：启动桥
.\build\Release\asio_bridge.exe
# 终端 2：播放任意音频（浏览器/播放器/游戏）
# 观察桥日志：目标 PID 出现、峰值 > 0、欠载=0 为佳
```

### 步骤 6：数值自检（先测后上线）
```powershell
.\build\Release\asio_bridge.exe --resampler-test   # 重采样器
.\build\Release\asio_bridge.exe --pll-test         # 速率锁+水位闭环仿真
.\build\Release\asio_bridge.exe --tube-test        # 300B 染色
.\build\Release\asio_bridge.exe --conv-test        # ASIO 类型转换
.\build\Release\asio_bridge.exe --capture-test     # 采集自检(渲染→回采比对)
.\build\Release\asio_bridge.exe --limiter-test     # 端点限幅器位置
```

### 步骤 7：开机自启（无窗口）
```powershell
pwsh -File tools\install_autostart.ps1            # 安装（登录触发、隐藏、失败自动重启）
pwsh -File tools\install_autostart.ps1 -Remove    # 卸载
# 日志：%USERPROFILE%\asio_bridge.log
```

### 步骤 8：日常使用
1. 启动桥（开机自动或手动）。
2. 播放任意应用音频——桥 10~20 秒内自动锁定「最响的渲染进程」。
3. 打开 http://127.0.0.1:3999 查看水位/速率锁/链路状态，按需开直通或染色。
4. 停止播放 → 桥自动跟随下一个目标；暂停/恢复自动重新 prime。

## 第五章 · 火候与调味（参数对照表 + 音质提升思路）

### 5.1 调参表（低延迟 ↔ 高稳定 光谱）

| 参数 | 位置 | 已验证取值 | 效果 |
|------|------|-----------|------|
| ASIO 缓冲帧数 | `--buffer` | 128（驱动锁 min=max） | 每帧 2.9ms；越小延迟越低 |
| 水位下限倍数 | 控制台 / asio_bridge.cfg `floor` | 8×缓冲 | 越大越稳越延迟；<8 欠载风险上升 |
| 重采样质量档 | 控制台 / cfg `src_taps` | 32=sinc（默认），0=线性 | sinc 高精度；线性低延迟 |
| 直通模式 | `--passthrough` / 控制台 | 关闭（默认） | 开则 ratio 恒 1.0 逐位直通 |
| TPDF 抖动 | `--no-dither` / 控制台 | 开（默认） | 关闭更纯净；开则转整数更顺 |
| 300B 染色 | 控制台 / cfg `tube_warmth` | 0.3 | 0=干净，1=明显暖 |

### 5.2 提升音质的思路（进阶菜谱，按性价比排序）

**已做到的（本菜谱）**
- 绕开混音/APO/音效——按 PID 旁路截流成立
- float32 全链路，输出 Int32LSB 全分辨率——RME WDM 的 16bit 截断消失
- 双环速率锁 + 分数重采样——漂移校正不再产生采样滑移，长时聆听更平滑

**下一步可以做的（思路清单）**
1. **多采样率自适应**：引擎混音格式随内容变化时，桥已能跟随采集端协商速率重建链路
2. **隔离播放链**：给音乐专用端点禁用一切引擎增强、固定 DeviceFormat，杜绝系统声音混入
3. **更高位深/DSD**：MADIface ASIO 支持 32bit 与 DSD，桥的转换层已预留类型通道
4. **时钟同步**：若未来用 ASIO 双向（采集+回放），用 ASIO 时间戳做精确时钟对齐

### 5.3 音质自检清单
- [ ] 专业声卡/DAC 屏幕速率 = 内容速率
- [ ] 桥日志 欠载=0、峰值<1.0（无削波）
- [ ] 应用音量 100%
- [ ] 目标端点属性里无任何增强
- [ ] 直通模式下播 44.1k 内容，控制台 ratio 恒 1.0

## 第六章 · 常见翻车点（全部实测踩过，附解法）

| 症状 | 根因 | 解法 |
|------|------|------|
| 加载 ASIO 驱动报 E_NOINTERFACE(0x80004002) | RME COM 对象只在 STA 公寓暴露接口 | 主线程 CoInitializeEx(STA) |
| 桥运行 4~5 秒必崩(0xC0000005) | STA 主线程阻塞式 COM 调用饿死 MADIface 回调 | 主线程零 COM 调用；枚举移 MTA 线程 |
| 自动发现目标一直失效(静默空结果) | 非 MTA 线程枚举会话 RPC_E_CHANGED_MODE | RunComOnMta 委托 MTA 工作线程 |
| 回环激活报 E_OUTOFMEMORY(0x8007000E) | 激活 handler 没实现 IAgileObject | 补 IAgileObject 接口 |
| 回环 GetMixFormat 报 E_NOTIMPL | 目标无活动流时回环客户端不支持 | 退目标端点混音格式，再退 16/2/44100 |
| 速率锁读数突跳 ±700ppm | 暂停/恢复突发污染窗口斜率 | 60s 短窗 + 500ms 断档截断 + 15s 清洁段 |
| 设备重启时采集线程崩溃 | 引擎释放 COM 对象后野指针调用 | SEH 兜底 + 设备事件通知重建 |
| 双重声 | 目标原声与桥副本同时出声 | 自动静音目标端点主音量(tap→redirect) |
| 开机弹 cmd 窗口 | 计划任务直启控制台程序 | wscript + VBS(窗口样式 0) 隐藏链 |
| ASIO 驱动被 DAW 占用桥起不来 | MADIface ASIO 单客户端 | 先停桥再用 DAW，反之亦然 |
