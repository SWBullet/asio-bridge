# 高保真音频直通 ASIO 桥 · 菜谱式指南

> **本菜名**：原味直通牛（Apple Music → RME ADI-2 Pro，不加系统调味料）
> **口味特点**：bit-perfect（比特透明）、零欠载、44.1kHz 全对齐
> **难度**：★★★★☆（需要 VS2022 + C++，全部坑已标注解法）
> **耗时**：首次约 2~4 小时（含调试）；照抄本菜谱约 1 小时
> **总延迟**：约 90~120ms（听音乐无感知，看视频请走系统路径）

## 第一章 · 成品清单（已确认的技术成果）

| # | 成果 | 一句话说明 |
|---|------|-----------|
| 1 | **应用→RME 的 ASIO 直通桥** | C++ + 官方 ASIO SDK 2.3，WASAPI 采集 → 环形缓冲 → MADIface ASIO 直出 |
| 2 | **STA 公寓定律（关键发现）** | RME 的 ASIO COM 对象(ThreadingModel=Apartment) **只在 STA 线程暴露接口**，MTA 下返回 E_NOINTERFACE |
| 3 | **ASIO 宿主禁律（崩溃根因）** | 绝不能在 ASIO 的 STA 主线程做阻塞式 COM 调用——会饿死 MADIface 回调，进程数秒内崩溃 |
| 4 | **VB-CABLE 固定速率实证** | 驱动内部速率**固定 44100Hz、不读注册表**；只有 GUI 控制面板(私有 IOCTL)能改；注册表值只是面板的记录 |
| 5 | **引擎周期锁定实证** | WASAPI 共享模式 periodicity 必须为 0，引擎周期锁 10ms；VB-CABLE 不支持独占采集 |
| 6 | **引擎格式持久化实证** | 混音速率以 PKEY_AudioEngine_DeviceFormat（每端点持久化）为准；直写注册表被 ACL 拒绝，须走端点属性存储 |
| 7 | **零欠载水位带配方** | 环形缓冲目标水位 = 8×ASIO 缓冲（2048 采样），丢弃阈值 +4096 → 实测零欠载 |
| 8 | **三保险自适应架构** | 命名事件握手 + SEH 野指针兜底 + ASIO 停滞看门狗(4 秒检测自动重建) |
| 9 | **无窗口开机自启** | 计划任务 + wscript + VBS(窗口样式 0)，三个开机任务全部无窗口 |
| 10 | **全参数实测基线** | 44.1kHz / 2ch / 128 帧 ASIO / VB-CABLE 缓冲 1536 / float32 全链路 / Int32LSB 输出 |

## 第三章 · 原理（这道菜为什么这么做）

### 3.1 完整数据流（成品上桌路径）

```
Apple Music ──PCM──▶ [CABLE Input 端点] ──▶ VB-CABLE 内核驱动(内部44.1kHz)
                                                     │ 虚拟电缆直通
                                                     ▼
                                            [CABLE Output 端点]
                                                     │ WASAPI 共享采集(float32, 引擎10ms周期)
                                                     ▼
┌────────────────── asio_bridge.exe ──────────────────────┐
│ 采集线程(MTA+MMCSS+SEH) ──float32──▶ 环形缓冲(SPSC无锁)  │
│                                            │ 水位控制    │
│ 主线程(STA: ASIO会话) ◀──统计/看门狗/握手  │             │
│                                            ▼             │
│                              ASIO回调(128帧=2.9ms)      │
│                              float32 → Int32LSB          │
└──────────────────────────────┬───────────────────────────┘
                               ▼
                   MADIface ASIO 驱动(madiface_asio_amd.dll)
                               ▼
                     ADI-2 Pro DAC ──▶ 耳机/音箱
```

### 3.2 三个"为什么"

**为什么用虚拟电缆截流？** 封闭应用（Apple Music、浏览器）只支持 WASAPI 共享输出，你无法给它装 ASIO 输出插件。让应用渲染到虚拟声卡端点，就拿到了它的干净 PCM。

**为什么不直接用系统路径到 RME？** 系统路径必然经过 audiodg 的混音/重采样/APO，且 RME 的 WDM 端点是 16bit 截断；MADIface ASIO 驱动才是唯一支持全位深/全采样率的通道。

**为什么桥需要环形缓冲？** 采集时钟（系统）与 ASIO 时钟（RME 硬件）独立运行，存在 ppm 级漂移；环形缓冲 + 水位控制吸收漂移和调度抖动，欠载用末样本保持、超水位丢弃多余采样。

### 3.3 bit-perfect 的成立条件（验收标准）

1. 内容采样率 = 44.1kHz 系（CD 16/44.1、无损 24/44.1 等）
2. 应用音量 = 100%（引擎才会原样传递）
3. CABLE 端点无 APO / 无「音频增强」
4. 只有目标应用渲染到 CABLE Input（多应用会在此混音）
5. VB-CABLE 面板内部速率 = 44100（与引擎 DeviceFormat 一致）

满足全部条件时：全链路仅发生 float32 格式转换（≤24bit 无损），零重采样、零量化损失。

## 第四章 · 制作步骤（复现指南）

### 步骤 1：备料
```powershell
# 安装 VB-CABLE（官网下载 Pack 后静默安装，需管理员）
VBCABLE_Setup_x64.exe -i -h
# 打开 VB-CABLE Control Panel：内部速率 44100、Max Latency 1536
```

### 步骤 2：搭工程
```powershell
git 或拷贝本仓库至 E:\Harness\asio-bridge（third_party 已含 ASIO SDK 2.3）
```

### 步骤 3：编译
```powershell
cmake -B build -S .          # VS2022 自带 CMake 在
# C:\Program Files\Microsoft Visual Studio\2022\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe
cmake --build build --config Release
```

### 步骤 4：首测（ASIO 链路验证）
```powershell
.\build\Release\asio_bridge.exe --tone --rate 44100
# 听到 1kHz 正弦、ADI-2 Pro 屏幕显示 44.1 → ASIO 链路 OK，Ctrl+C 停止
```

### 步骤 5：全链路测试
```powershell
# 终端 1：启动桥
.\build\Release\asio_bridge.exe
# 终端 2：向 CABLE Input 灌 8 秒 440Hz 正弦
pwsh -File tools\test_render.ps1 -Seconds 8
# 观察桥日志：峰值 > 0 说明音频穿过整条链；欠载=0 为佳
```

### 步骤 6：开机自启（无窗口）
```powershell
pwsh -File tools\install_autostart.ps1            # 安装（登录触发、隐藏、失败自动重启）
pwsh -File tools\install_autostart.ps1 -Remove    # 卸载
# 日志：C:\Users\Administrator\asio_bridge.log
```

### 步骤 7：日常使用
1. 应用输出设备选「CABLE Input (VB-Audio Virtual Cable)」
2. 播放 → 声音经 ADI-2 Pro 直出（屏幕显示 44.1）
3. 看视频/游戏 → 把该应用输出切回 RME 端点（走系统路径）

## 第五章 · 火候与调味（参数对照表 + 音质提升思路）

### 5.1 调参表（低延迟 ↔ 高稳定 光谱）

| 参数 | 位置 | 已验证取值 | 效果 |
|------|------|-----------|------|
| ASIO 缓冲帧数 | RME MADIface Settings | 128（驱动锁 min=max） | 每帧 2.9ms；越小延迟越低 |
| VB-CABLE Max Latency | 控制面板 | 1536（最小档，原默认 7168≈162ms） | 电缆内部缓冲，**单项最大延迟来源** |
| VB-CABLE 内部速率 | 控制面板 | 44100 | 唯一能改驱动速率的入口(GUI IOCTL) |
| 环形水位目标 | main.cpp wTarget | 8×缓冲=2048 采样 | 越大越稳越延迟；512→欠载爆炸、1024→偶发欠载 |
| 采集周期 | 不可调（实测） | 引擎锁 10ms | 共享模式 periodicity 必须为 0 |

### 5.2 提升音质的思路（进阶菜谱，按性价比排序）

**已做到的（本菜谱）**
- 绕开混音/APO/音效——单应用截流成立
- float32 全链路，输出 Int32LSB 全分辨率——RME WDM 的 16bit 截断消失
- 44.1kHz 采样率全对齐——无重采样

**下一步可以做的（思路清单）**
1. **多采样率自适应**：换支持独占采集/动态格式的虚拟声卡（VAC 值得实测），桥的握手/格式写入机制已备好，可实现 44.1k/48k/96k 按内容切换
2. **分数重采样漂移校正**：把水位丢弃换成窗口 sinc 分数重采样器——漂移校正本身不再产生采样滑移，长时聆听更平滑
3. **消除 VB-CABLE 内部缓冲**：自研 AVStream 虚拟驱动（需要 EV 签名证书），直通采集独占模式，延迟可到个位数毫秒
4. **隔离播放链**：给音乐专用虚拟端点禁用一切引擎增强、固定 DeviceFormat，杜绝系统声音混入
5. **更高位深/DSD**：MADIface ASIO 支持 32bit 与 DSD，桥的转换层已预留类型通道
6. **时钟同步**：若未来用 ASIO 双向（采集+回放），用 ASIO 时间戳做精确时钟对齐

### 5.3 音质自检清单
- [ ] ADI-2 Pro 屏幕速率 = 内容速率
- [ ] 桥日志 欠载=0、峰值<1.0（无削波）
- [ ] 应用音量 100%
- [ ] CABLE 端点属性里无任何增强
- [ ] 播放期间 CABLE Input 只有目标应用

## 第六章 · 常见翻车点（全部实测踩过，附解法）

| 症状 | 根因 | 解法 |
|------|------|------|
| 加载 ASIO 驱动报 E_NOINTERFACE(0x80004002) | RME COM 对象只在 STA 公寓暴露接口 | 主线程 CoInitializeEx(STA) |
| 桥运行 4~5 秒必崩(0xC0000005) | STA 主线程阻塞式 COM 调用饿死 MADIface 回调 | 主线程零 COM 调用；检测移出主线程 |
| 设备重启时采集线程崩溃 | 引擎释放 COM 对象后野指针调用 | SEH 兜底 + 握手机制先释放流 |
| 同一客户端连续两次 Initialize 崩溃 | 失败后引擎残留半初始化状态 | 失败必 Release + 重新 Activate 再 Initialize |
| 改注册表速率无效 | VB-CABLE 驱动不读注册表，固定 44.1k | 用控制面板 GUI(IOCTL)改，桥看门狗自动跟随 |
| 桥重开后仍是旧速率 | 引擎按 DeviceFormat 持久化恢复；直写注册表被 ACL 拒绝 | 桥经 IPropertyStore 写 PKEY_AudioEngine_DeviceFormat |
| 共享模式请求 3ms 失败 | 共享模式 periodicity 必须为 0 | 接受 10ms 周期（硬限制） |
| 水位 512 目标 → 每秒欠载 | 10ms 采集突发(882采样)决定水位下限 | 目标水位≥8×ASIO 缓冲(2048) |
| 开机弹 cmd 窗口 | 计划任务直启控制台程序 | wscript + VBS(窗口样式 0) 隐藏链 |
| ASIO 驱动被 DAW 占用桥起不来 | MADIface ASIO 单客户端 | 先停桥再用 DAW，反之亦然 |
